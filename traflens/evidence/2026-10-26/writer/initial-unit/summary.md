# CKwriter safe reconnection checkpoint

Base source: befff1df27323f8215c4f34b5cb022202c1f0d59. Only ckwriter.go, new write.go and write_test.go were changed. Source hashes and exact commands are in metadata.json. Production source is frozen for root review/commit/build.

The writer uses ch-go v0.69.0. The old Cache.Write resets the serialized columnBlock after Dial failure or the first Do error, losing already released CKItems. The new path retains this block and its row order until a logical batch finishes, limits attempts to3 under a shared10s context, and closes/removes failed clients before redial. Reset, timestamp and endpoint rotation occur once. No extra Ping RTT is added to successful batches.

Input safety is based on the current INSERT VALUES path with no SQL inline rows or ExternalData. A zero-row first-column adapter still delegates type inference. Its matched first-column sample marks sampleSeen. First OnInput checks the driver child context, marks inputStarted before restoring the real column, then allows encoding. Subsequent callback replaces only the first row-count view with zero before io.EOF, preventing ch-go's duplicate EOF-tail behavior. Real StateEncoder/Preparable interfaces remain on the restored column during encoding.

Real native-protocol tests caught a close-channel race: receiver closes column-info before errgroup cancellation, allowing a sender to observe nil metadata. Without sampleSeen, OnInput now waits for its driver context cancellation, preserving receiver's original EOF/Exception as the first errgroup error and never supplying rows. An empty-metadata clean EOS is bounded by the outer deadline. The failed initial uncommitted prototype log remains as unit-initial-gate-race.log; it is not presented as an untouched upstream baseline.

Only pre-input connection/EOF errors with available budget are replayed on a fresh client. Once inputStarted, any error is uncertain: it may have committed and no blind replay occurs, including no endpoint switching. WriteUncertainCount counts those rows as a subset of WriteFailedCount; final success/failure row counts are each recorded once. RetryCount and RetryFailedCount count extra attempts, not rows.

Validation:12 top-level tests, with stale-idle and before-input subcases, all pass (unit-final.log,0.561s). The full module passed race10 rounds (race-repeat.log,5.545s). Both critical pre-input disconnection subcases passed race25 rounds (stale-idle-race-repeat.log,6.319s). Tests use actual vendored ch-go with a native protocol peer over net.Pipe, with no listener port or external database. They verify supplied row values/order after CKItem poisoning on Release, DateTime inference, successful single-block EOF behavior, lost-ACK non-replay, preserved server Exception, retry limits/budget, final counters/Reset, optional column interfaces and live-client reset.

Limits: driver cancellation may add up to its existing1s cleanup beyond the10s context. Immediate refusal can consume the two100ms backoffs in about200ms, so a long outage can still fail/drop batches; root explicitly chose real restart measurement before tuning. DDL/initialization still uses its existing separate path. This is not a zero-loss, exactly-once, full Server build or real ClickHouse durability claim. Root owns official build and lab injection; this subtask started/restarted no service and produced no traffic.
